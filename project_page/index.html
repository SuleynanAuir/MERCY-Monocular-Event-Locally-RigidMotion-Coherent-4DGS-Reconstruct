Coherent motion from a fixed viewpoint

A fixed monocular view provides limited geometric observations. Estimating each Gaussian’s motion independently can cause inconsistent deformation. Mercy uses a part-aware Gaussian representation: moving components share rigid transformations, while static components remain fixed.

Starting from the first RGB frame, the pipeline initializes and refines a canonical Gaussian model, identifies moving parts, and estimates continuous motion through a kinematic structure. Rendering and event-based supervision jointly refine motion. Evaluation uses nine Blender objects, rendered RGB videos and ESIM-generated event streams.

Method

Geometry, part motion and events work together

01Initialize and align

Hunyuan3D 3.1 → Mesh2Splat → CARE-GS

The first frame supplies appearance and structural cues. Hunyuan3D generates a static mesh, and Mesh2Splat converts it into canonical Gaussians. CARE-GS aligns the camera and refines appearance, silhouettes and geometry, establishing correspondence between image observations and the 3D model.

02Constrain motion by parts

PartField · FEAST · MonoGS · Kinematics

PartField assigns Gaussian part labels. FEAST uses flow and event-assisted temporal contours to separate dynamic and static parts. MonoGS provides motion estimates; joint pivots and a parent–child tree organize local rigid motion. Catmull–Rom interpolation and forward kinematics produce smooth component poses.

03Refine with event supervision

MotionFineTuner · Multi-scale events · Joint optimization

Static components remain frozen while motion refinement adjusts joint rotations and spatial transformations. Multi-scale event encoding captures both outlines and local details. Rendering and event supervision jointly optimize the moving Gaussian representation.
