# Arm / Robot / Gears / Rotation 六面动画

本轮按用户确认的展示定义接入：V1 为已有 corrected_g0.ply；V2 为原始物件 PLY；V3 为从已有 Blender 表面约束重采样的高斯。沿用现有版本映射层，内部原始标签 V1/V2 在显示时交换，源文件及哈希保留。

仅使用 `pipeline=observations`，与 Hybrid FVV 分离。每个物件独立进程、CPU 逐帧缓存，UI 原有六相机预渲染播放和 RGB/Event 面板保持不变。数据与中间文件存于忽略目录 `outputs/six-object-preview/` 和服务器 `/root/autodl-tmp/four-object-six-preview-20261101/`，不进入 Git。

## 数据和运动来源

- Arm：26 帧，30 fps；Gears：25 帧，30 fps；Rotation：40 帧，30 fps。复用源表面配准、刚体部件绑定及表面高斯重采样流程。
- Robot：24 帧，30 fps。源文件有局部非刚体形变，原刚体导出器正确拒绝。`export_deforming_surface.py` 校验固定相机、固定拓扑并导出每帧实际三角面；`prepare_deforming_object.py` 按面内坐标搬运高斯位置、局部偏移和旋转。尺度保持原值，因此不是完整的形变协方差求解。
- 时间映射使用源帧 `1 + i * frame_step` 与 RGB 的第 i 帧；由相机元数据的初始帧及 RGB 长度确定。Arm/Gears 的 Blender 文件默认播放范围与实际 RGB 帧数不一致，独立导出包装器只修改内存中的范围，未保存或覆盖源 blend。
- 这是显式源几何辅助的动画绑定与表面候选生成，不是新的事件训练，也不保证 V3 在全部角度优于 V1/V2。原始模型、已有修正版均保留。

## RGB/Event

`prepare_raw_event_references.py` 从原始 MKV 解码 RGB，从原始 `(x,y,t,p)` NPY 按 `(上一帧时间, 当前帧时间]` 累积事件。红色表示正极性，蓝色表示负极性；RGB 不做背景替换。检查坐标范围、极性、有限值、单调时间和视频长度，输出无损 PNG 双面板和来源 SHA256。所有事件均进入对应时间窗：Arm 2644381、Robot 6612966、Gears 3319078、Rotation 695710。该检查不是独立传感器标定证明。

RGB/Event 参考是源固定相机画面。六面切换改变三维高斯相机，参考面板不会伪造其他视角的 RGB/Event。
