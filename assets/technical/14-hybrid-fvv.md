# Hybrid 3D-4DGS 实时自由视角浏览（第一阶段）

## 状态与边界

当前采用已验证的累计 52000 步 Lego 权重，名称显示物件与训练完成时间。2026-10-30 按用户要求清除历史模型，只保留当前模型。**960×640、高画质、4800 帧／87.91 秒实测网络＋JPEG 解码 54.60 FPS**；不是浏览器显示帧率。默认目标 90 FPS，可选 60／120；实际表现受 GPU、网络和屏幕限制。本轮续训遇到 CUDA 非法内存访问，未发布新权重；新增细节改善来自图像传输保真。文末及 [最新验收记录](14-hybrid-fvv-smooth-detail.json) 为当前状态，前文各轮指标及回退说明属于历史记录。

上游：[Hybrid 3D-4D Gaussian Splatting](https://github.com/ohsngjun/3D-4DGS)。采用其静态 3D＋动态 4D 联合光栅器，不是本项目已有的 Mesh＋GS `hybrid` 显示模式。上游配置为 6000 次训练，但耗时依赖数据量、分辨率、GPU 和高斯数量。“分钟级”是首阶段实测目标，不能通过降低原模型质量来冒充达标。

本实现不把 MERCY 的 NPZ／PLY 当成 Hybrid 检查点。新模型需来自上游训练或已有上游检查点。单目视频、事件流及现有部件绑定不能直接转换成完整的标定多视角训练集；本阶段不新增该数据重建算法。

导入接受一个 ZIP：根目录**且仅有** `model.pth`、`effective.yaml`、`manifest.json`。例如在已有 Hybrid 产物目录执行：

```bash
python -m zipfile -c lego-model.zip model.pth effective.yaml manifest.json
```

页面提供上传字节进度；上传完成后校验固定文件名、场景、上游版本和模型／配置 SHA-256，再加载到 GPU。加载失败时保留原模型。不能直接导入原 MERCY PLY／NPZ 或缺少配置的任意 PTH。模型包需来自受信任的 Hybrid 训练产物；检查点仍使用 `weights_only=True`。

上传上限 512 MiB，解压上限 1 GiB，元数据文件各不超过 128 KiB；拒绝目录穿越、符号链接和额外文件。导入与离线训练写入互斥，继续遵守模型父目录 8 GiB 总预算；重复模型与配置哈希直接复用已有产物，临时上传文件在成功／失败后移除。训练日志只在内存保留末尾 8 KiB，训练指标和一个最终推理检查点落盘。

## 架构与隔离

原 UI → “实时动态浏览高斯” → `/fvv?scene=...` → 同源 WebSocket 网关 → 独立 Hybrid Python/CUDA 进程 → 当前时间与自由相机的即时高斯渲染。

按钮在当前标签页进入独立页面，使原 UI 的连接随页面退出而释放；返回保留 scene 查询参数。原训练、渲染、质量设置、版本对照及实验导出没有改变。旧 UI 仅增加入口与四个独立路由。多物件代理也安装相同路由；必须同时更新提供 HTML/JS 的 asset upstream 才能显示按钮。

同一服务只加载一个场景、允许一个活跃浏览连接；scene 不匹配或服务忙碌会明确拒绝。浏览模式按需重新渲染，无预渲染视频替代。WASD 移动、QE 升降、拖动旋转、滚轮移动、视野调节、暂停／时间拖动／循环播放；初始位置为模型世界坐标，打包时用 `--position/--yaw/--pitch` 设置。

## 独立部署环境

在 Linux NVIDIA CUDA 机器上另外克隆上游，记录 `git rev-parse HEAD`。不要安装到 MERCY 原环境，不要替换原光栅器。适配器启动时将上游目录置于自身导入路径首位，以避免两项目同名 `scene/utils/gaussian_renderer` 冲突。

上游 `environment.yml` 固定 Python 3.7 / PyTorch 1.12；本适配器需要 **Python ≥3.10**；已增加 PyTorch 2.1 tensor-only 检查点兼容。原始检查点若包含 NumPy 标量，安全打包需使用 PyTorch ≥2.4 的 allowlist 接口，运行打包后的纯张量产物可使用 2.1。应在独立环境安装与服务器 CUDA 工具链匹配的 PyTorch/torchvision，然后按上游依赖安装并编译 `simple-knn`、`pointops2` 和其 Hybrid 光栅器。这里没有假定旧版 environment.yml 可直接运行本适配器；本次已验证上述 PyTorch 2.1.2/CUDA 12.1 组合可编译并运行，其他组合仍需部署实测。

```bash
# 在独立 Hybrid 环境中执行，MERCY_ROOT 和 HYBRID_ROOT 为绝对路径
pip install -r "$MERCY_ROOT/requirements/fvv.txt"
# 在 HYBRID_ROOT 检查实际的上游导入和 CUDA 扩展
python -c 'import torch; from scene import GaussianModel; from gaussian_renderer import render; assert torch.cuda.is_available()'
```

可通过 `CUDA_VISIBLE_DEVICES` 选用独立 GPU。若与原服务共用 GPU，即使代码与画质不变，显存和算力竞争仍可能影响原服务速度；要求同时无性能影响时，应分配不同 GPU。

## 离线训练与加载

输入要求：上游预处理后的 Blender 格式动态标定数据、`transforms_train.json`、相应 test/val JSON、图像和已存在的 `points3d.ply`。拒绝在输入目录生成初始点云，也不接受优先走 COLMAP 分支的 `sparse` 目录。数据预处理单独执行并计入自己的存储预算。不要把此路径指向不匹配的现有 MERCY 数据。

### 训练新模型

```bash
python "$MERCY_ROOT/scripts/fvv/hybrid.py" --repo "$HYBRID_ROOT" train \
  --config "$HYBRID_ROOT/configs/n3v/default.yaml" \
  --source /data/hybrid-prepared/scene \
  --output "$MERCY_ROOT/outputs/fvv/lego-run-001" --scene lego \
  --budget-gib 8 --total-budget-gib 32 --max-minutes 30 \
  --position 0 0 -3
```

沿用输入配置的训练参数，不偷偷减少迭代、点数、SH 阶数或分辨率。独立包装器关闭 TensorBoard 图像／直方图日志和逐阶段副本，只在最终迭代评估并保存一个用于推理的检查点。它不提供优化器断点续训；若需要完整训练检查点，请在另一个有预算的上游训练任务中保留。`--max-minutes` 是超时停止条件，不是完成时间承诺。记录实际时间至 `timing.json`。

### 已有上游模型

```bash
python "$MERCY_ROOT/scripts/fvv/hybrid.py" --repo "$HYBRID_ROOT" pack \
  --config /models/source-training-config.yaml \
```

配置必须对应原始训练（特别是时间范围、frame_ratio、SH、4D rotation、背景和管线选项）。采用 `weights_only=True` 加载；PyTorch ≥2.4 仅额外允许 NumPy 标量／dtype 构造器，不允许任意 pickle 全局对象。第一阶段支持 28 字段 Hybrid 4D 检查点，暂不支持环境贴图。所有推理参数保持 dtype 和数值；仅移除优化器、梯度累计及训练半径统计。源检查点不修改；输出目录必须不存在。

### 网络流水传输优化（2026-10-30）

服务器通过 `max_in_flight: 3` 告知页面支持有界流水传输。页面允许最多三条尚未完成解码的请求，同时将发送频率限制到 60 Hz；解码完成即归还额度并尝试发送最新相机，避免额外等待下一次动画回调。JPEG 仍为质量 92、无色度降采样，模型精度、输出分辨率和 SH 不变。服务端继续按请求顺序即时渲染，不预生成视频。

解码通过 Promise 串行执行，只有释放位图后才能归还额度，防止异步解码乱序或慢客户端无限堆积；页面隐藏／连接关闭时失效全部旧任务。仅当图像尺寸变化时重设 canvas 尺寸，避免每帧重建绘图缓冲。旧服务器未声明能力时仍退回单帧请求模式。

三帧窗口以少量在途延迟换取网络吞吐，不能消除网络本身的往返延迟。验收同时记录帧间隔和请求至解码延迟，不能只看 FPS。可用相同模型、相同 GPU 空闲条件对比：

```bash
python scripts/fvv/probe_service.py --url http://127.0.0.1:21896/fvv \
  --scene lego --frames 180 --window 1
python scripts/fvv/probe_service.py --url http://127.0.0.1:21896/fvv \
  --scene lego --frames 3000 --window 3
```

这些测量包含真实网关、SSH、GPU 和 JPEG 解码，不包含浏览器绘制。单次长测需检查输出的 `duration_seconds` 确实不少于 60 秒。

## 存储与资源策略

| 项目 | 默认约束 |
| --- | --- |
| 单次离线任务目录 | 8 GiB；可调，超限失败 |
| 同父目录产物总量 | 32 GiB；开始前预留单任务空间 |
| 磁盘空余 | 至少额外保留 1 GiB |
| 训练写入 | 父目录互斥锁；并行写入任务拒绝启动 |
| 检查点序列化 | 限额 writer，`.partial` 完成后原子替换 |
| 其他上游中间文件 | 250 ms watchdog；超限终止进程组，不发布 ready 清单 |
| 副本／历史 | 一个紧凑检查点；无每帧 PLY、无时间序列烘焙 |
| 浏览磁盘缓存 | 0；不保存图像、视频或相机缓存 |
| 浏览内存 | 单模型、单浏览者；最多三帧在途，串行解码，性能记录最多 300 个样本 |
| 后台／断开 | 页面隐藏断开流，解码后释放 ImageBitmap |

总预算以 `--output` 的**父目录**为边界，因此全部 FVV 版本应放在同一个专用 `outputs/fvv/`。不自动删除旧模型、活动模型或失败目录；总预算耗尽后明确拒绝任务，操作者可检查并删除确认不用的 FVV 目录。失败后清单撤下，残留文件仍计入预算。若进程被操作系统强杀导致锁残留，确认无任务运行后再删除 `.fvv-writer.lock`。

watchdog 是软上限，上游的一次大文件写入可能在 250 ms 内超出预算。需要严格硬上限时，把专用产物目录放在启用 project quota 的文件系统／有容量限制的独立卷上。上游代码、依赖、预处理数据和用户自行重定向的控制台日志不属于产物预算，需单独限制；程序本身不追加日志文件。

JPEG 92、无色度降采样，仅用于新页面传输；它是有损显示编码，不承诺与浮点渲染逐像素一致。原模型、原页面渲染和导出编码不变。新页面不会为了提高 FPS 自动裁剪高斯或降 SH；因此硬件不达标时会明确显示低帧率。

## 验收标准与命令

1. **原功能回归**：相同原资产／相机／时间／设置下原渲染输出不变；原选择、V1/V2/V3、参考帧、播放、实验导出可用。已有 CPU/UI 测试通过不代替 GPU 图像一致性实测。
2. **真实 FVV**：连续移动、转身、升降到未训练视角，暂停时间检查遮挡／透视；动态播放时相机仍可移动。确认使用当前 scene 的 manifest/hash；未配置不得播放替代视频。
3. **画质一致性**：同一原始 Hybrid 检查点及配置，在多个时间／视角比较打包前后浮点图像，最大绝对误差 ≤1e-6；不要用 JPEG 截图代替。新训练模型与原 MERCY 模型不是相同方法，不能由打包一致性推导两者重建质量相同。
4. **实时性**：目标 GPU＋网络＋浏览器上，960×640 连续旋转移动播放至少 60 秒，显示平均 ≥30 FPS、p95 帧间隔 ≤50 ms、p95 请求至显示 ≤100 ms。分别记录 GPU 型号、显存、模型点数与大小、网络条件、浏览器和分辨率；不以服务端 FPS 代替端到端 FPS。
5. **分钟级**：记录完整离线墙钟（加载、训练、最终评估、写盘），首阶段目标 ≤10 分钟；30 分钟默认超时只是保护阈值。若不达标如实报告，不自动改变质量参数。
6. **存储**：用小预算验证拒绝／中止；连续浏览 10 分钟磁盘占用不增长；反复开关／拖动／进入后台后内存不持续增长。检查失败产物不可作为 ready 加载，旧资产哈希不变。

### 2026-10-30：播放期间铲臂／铲子闪烁修正

独立 FVV 服务增加显式参数 `--temporal-sigma 0.016666666666666666`，目前 Lego 服务已启用。省略参数或以 `--temporal-sigma 0` 重启可回退原生内核。训练与原有浏览服务不使用此参数；模型权重、相机、空间协方差、运动轨迹和 JPEG 质量保持原值。

`scripts/fvv/temporal_kernel.py` 在独立缓存内编译推理扩展，要求固定上游提交和精确源码匹配，失败时停止加载并报错。它将 rot4D 的固定 5% 时间支持硬剔除改为像素 alpha 的 1/255 可见性界限，并对时间不透明度作标准差 1/60 秒的高斯预滤波及积分补偿。不混合历史图像，不冻结时间。该参数只支持 CUDA rot4D 路径，不用于训练反向传播。扩展在服务进程内选择，不能在同一进程混用原生与滤波 Renderer；A/B 检查脚本会逐组显式切换。

RTX 2080 Ti 实测结果见 [时间稳定性记录](14-hybrid-fvv-temporal.json)。固定相机 640×640、63 个时间点，各取间隔 1/240 秒的三个连续时刻，铲子／铲臂区域的二阶时间差均值下降 **5.08%／6.87%**。这项指标也包含真实运动，不能直接等价为主观闪烁减少比例，更不能证明完全消除闪烁。20 张已用于开发评估的留出图像 PSNR 36.6005 → 36.7568 dB，前景 PSNR 30.2412 → 30.4634 dB，边缘误差 0.015233 → 0.015116，SSIM 0.989848 → 0.989842（微小下降）。渲染与 JPEG 平均耗时 8.97 → 8.68 ms；不是浏览器 FPS。

复现：在独立 GPU 环境运行 `python scripts/fvv/check_temporal.py --repo "$HYBRID_ROOT" --model /data/hybrid-lego/models/lego-18000-v1 --dataset /data/hybrid-lego/dataset-v1 --output /tmp/temporal-check.json`。检查使用真实模型与原始 RGB。最终扩展源文件及编译缓存合计约 22 MiB，内容指纹命名、重复启动复用，无逐帧磁盘缓存或额外模型副本。后续升级仅保留正在使用的扩展版本。

### 铲子／铲臂专项训练（第二轮修正）

### 滚轮拉远时的遮挡与多视角训练

用户确认的问题是滚轮移动相机后模型在画面中变小。实际 GPU 复现发现铲子变暗、局部叠层，以及地面外侧的漂浮条带。仅调整二维高斯滤波不足以修正这一现象；固定相机监督无法约束离开原视点后的几何和遮挡。浏览器滚轮仍然执行真实相机平移，没有改成只改变 FOV 的数字缩放。

利用项目已有 `Lego.blend` 动画场景补充拉远视角，原文件只读，以 Blender `--background --disable-autoexec` 离线渲染。`render_lego_multiview.py` 将源场景相机通过既有 initial registration 和数据集坐标变换映射到高斯空间，使用 40 个动画时刻、0.5/1.5 两个后退距离，共 80 张 640×640、32 samples 加降噪图像，其中 70 张用于训练、10 张保留验证。这些是**提供的源场景生成的监督图像，不是新拍摄的真实多视角数据**。原视频第 0–398 帧继续参与每一步训练。

独立验收集使用第 77、151、307 帧与 0.25、0.75、1.0、2.0 四个未参与训练的距离，共 12 张参照图。时间点在原相机视频中可见，因此这里验证的是新视角，不是新动作泛化。原相机同时间源场景与原视频的 PSNR 分别为 41.36、41.18、40.20 dB，用于核对动画时间与坐标变换。

### 2026-10-30：自由视角与六面观测隔离

原页面的“暂时无法渲染”来自原三版本 Lego 渲染服务，而非 Hybrid `/fvv`。服务器首次错误落在中间版本 `GaussianPairRenderer` 的 GPU 图像回传；后续 CUDA 同步持续报非法访存，说明进程上下文已失效。降低分辨率不能恢复这种故障。首次错误的具体 GPU 算子仍需同步模式实测定位，不能把两种模式共用队列直接认定为 CUDA 根因。
