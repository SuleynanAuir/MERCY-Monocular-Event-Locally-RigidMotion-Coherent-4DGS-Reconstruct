# Bind-GS 部件绑定动画基线

Bind-GS 是本文为 V1 定义的名称，意为通过部件绑定驱动的高斯。它复用 Blender 已有动画，不训练 SC-GS 控制节点网络。输出仍然是动态高斯，Blender 网格不是 GS 模式的直接渲染对象。

## 1 输入与身份记录

输入包括初始高斯 PLY、Blender 场景、相机参数，以及动画采样设置。PLY 中的位置、四元数、尺度、不透明度和颜色构成实际显示的资产。G0 的制作来源需要单独记录，不能因为后续渲染使用高斯就声称其上游没有 Blender 信息。

运行前记录输入文件哈希、帧数、首帧、时间单位和相机坐标约定。确认 G0 对应动画起始姿态；若初始状态不一致，后续正确的 Object 矩阵也不能消除配准误差。保留原始文件，产物写入新的目录。

输出是输入清单及明确的首帧对应关系。检查点是 PLY 字段有效、四元数可归一化、相机与模型处于可对应的坐标系。

## 2 从 Blender 导出表面与动画

[export_blender_parts.py](../../scripts/motion/export_blender_parts.py) 在 Blender 内运行，从场景对象中筛选可用网格，提取初始表面采样点与部件标签。逐帧设置场景时间，读取求值后对象的 `matrix_world`；带变形的对象还导出逐帧表面顶点。

关键数组包括 `rest_points`、`point_parts`、`object_matrices`、`source_frames`、`part_offsets` 和相应的 `deformed_*`。元数据保存对象名、采样起点和步长。脚本默认采样设置不是所有数据的通用时间标定，必须与本次视频对应。

输出归档中的动画是源动画，不是从视频或事件估计的新运动。检查采样范围没有越过源动画，部件顺序和标签一致，弹性部件的顶点对应关系在各帧保持一致。

## 3 配准两个坐标系

[bind_lego_parts.py](../../scripts/motion/bind_lego_parts.py) 用相机信息提供初始配准，再用稳健相似变换 ICP 对齐 Blender 表面与高斯位置，也可读取已验证的配准文件。

记配准矩阵为 A，它把 Blender 世界坐标映射到高斯坐标。配准仅确定两套资产的对应关系，不重新生成高斯几何。应检查误差分位数和多视角重叠情况，尤其是机械臂、连杆与关节附近；一个整体误差均值不能证明所有细部均对齐。

输出是 `registration` 及误差记录。若比例、方向或初始姿态错误，应先修正输入或配准，不能通过放宽绑定距离掩盖问题。

## 4 分配部件绑定

对每个高斯查询对齐表面的最近采样点，并继承其部件标签。根据源矩阵判断部件是否运动，结合最大附着距离选择动态高斯。绑定归档保存 `labels`、`nearest_vertex`、`dynamic_indices`、距离及配准矩阵。

最近邻是一种几何推断，不是真实部件分割。两个零件接近时可能误绑；离表面太远的高斯不会自动进入运动组。应按部件着色检查边界，并查看未绑定行是否落在机械臂主体上。误绑与未绑定需要分别统计。

## 5 计算刚性部件的逐帧姿态

[ArticulatedBaker](../../utils/articulated_motion.py) 对部件 j 计算相对首帧变换：

```text
D_j(t) = A · M_j(t) · inverse(M_j(0)) · inverse(A)
x_i(t) = R_j(t) · x_i(0) + T_j(t)
q_i(t) = quaternion(R_j(t)) ⊗ q_i(0)
```

其中 M 是 Blender Object 矩阵，R、T 来自 D；i 是绑定到部件 j 的高斯。首帧使用恒等变换。尺度和外观不由这个刚体运动步骤学习。同部件点对距离应保持不变，旋转矩阵应满足正交性和正行列式检查。

输出是动态高斯的位置和四元数。刚体内形状保持不等于跨部件表面一定接合：初始几何误差和绑定边界仍会影响关节外观。

## 6 处理弹性带

刚体矩阵无法表示弹性带伸缩。实现从源动画中取出每帧变形表面，在局部邻域通过 SVD 拟合旋转，将附近高斯相对初始表面的偏移映射到当前表面，再更新朝向。

这是局部刚性近似，保留 splat 形状但不等于真实弹性求解。检查顶点身份、数值有限性、局部连续性和遮挡变化；不能将这一步解释为质量、受力或能量守恒模拟。

## 7 缓存与渲染

[cache_lego_initial_motion.py](../../scripts/motion/cache_lego_initial_motion.py) 逐帧调用姿态计算，写出 `poses.npy`、`dynamic_indices.npy` 及渲染缓存。缓存姿态每行包含 XYZ 和四元数，读取端必须核对数组布局与高斯行号。

渲染时把动态行的位置、朝向替换为本帧姿态，静态行保持初值，再由 Gaussian rasterizer 成像。时间在这里用于选取已有姿态，不是送入 MLP 预测运动。

输出包括可重载的动画缓存和抽检画面。应比较缓存前后同帧、同相机的渲染，验证序列化没有改变行号、坐标或四元数顺序。

## 8 验证与问题定位

先看完整运动周期，再逐帧查看关节和细杆，并在固定时刻切换观察视角。断臂检查按“初始覆盖、配准、部件标签、未绑定行、弹性近似”的顺序定位，不能仅凭渲染缺口推断源动画错误。

该阶段交付的是动画先验驱动的基线。它回答运动能否被正确转移到高斯，不回答能否从观测独立恢复运动。
